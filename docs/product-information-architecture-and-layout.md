# Note Down 产品信息架构与页面布局

> 版本：1.3 Today 天气日历基线
> 日期：2026-07-22
> 状态：统一文档集合与 Today 天气日历卡已实现；不设收件箱与辅助面板。

## 1. 为什么重做

初版把 Daily Note 的最小纵向链路直接做成了应用骨架，造成三个问题：

1. 独立日历页面或临时面板割裂了 Daily 的时间上下文与写作入口。
2. 文章、收藏、任务和项目只有导航占位，没有表达彼此关系。
3. “知识库”成为含义模糊的兜底入口，无法回答内容是什么、现在处于什么状态、属于哪个项目。

新版先分离四个正交维度，再设计界面：

- **时间**：今天、某一天、计划日期。
- **状态**：进行中、已归档、已发布。
- **内容类型**：笔记、文章、收藏、任务。
- **上下文**：项目、标签。

同一条内容可以同时回答四个问题，例如：

> 这是一篇文章，尚在草稿阶段，属于 Note Down 项目，计划周五发布。

第三方清单只能证明这些依赖包含在当前产品中，不能证明每个页面都使用了每一项依赖。

Codex 值得借鉴的不是“用了 Electron”本身，而是它的工作区模型：

- 项目侧栏负责稳定上下文。
- 主区域始终只突出当前任务。
- 笔记、文章、收藏和项目都是同一文档库的不同集合视图。
- “今天”在正文顶部直接提供天气氛围与日期导航；所有核心任务都在主区域完成。

## 3. 竞品模式与取舍

| 产品 | 借鉴 | 不照搬 |
| --- | --- | --- |
| Codex | 项目侧栏、对象列表、主工作区、按需检查器 | 线程和 Git 语义不适合直接映射为笔记 |
| Reflect | Daily Note、快速捕获、紧凑日期导航、写作专注 | 不做反向链接和关系图谱 |
| Obsidian | Markdown 真源、文件可移植、属性、保存视图、命令面板 | 不让文件树和插件配置成为默认体验 |
| Craft | Daily、文档层级、Collection 的表格/画廊视图 | 不使用不可移植的专有块格式作为真源 |
| Capacities | Daily 是低摩擦入口，内容之后转成项目、任务或长文 | 不引入完整对象图和反向链接体系 |
| Readwise Reader | 多种收藏内容、阅读视图和组合过滤 | 不引入全局 Inbox，也不把阅读器做成产品首页 |
| Raindrop | 集合、标签和视觉收藏布局 | 不引入 Unsorted，也不把项目简化为收藏文件夹 |
| Things | 时间视图与项目上下文分离 | 不引入 Inbox，也不复制完整 GTD 系统 |
| Linear | 项目 Hub、状态、活跃度、不同视图共享同一数据 | 不引入团队、周期和复杂路线图 |
| 成熟块编辑器 | `/` 命令的搜索、分组、键盘导航、懒加载 | 不引入组织协作组件数量和业务广度 |

## 4. 核心内容模型

### 4.1 一等实体

| 实体 | 用途 | Markdown 内容 | 关键状态 |
| --- | --- | --- | --- |
| Daily | 每天的连续记录容器 | 是 | 日期 |
| Note | 随手记、短笔记、一般文档 | 是 | Active / Archived |
| Article | 长文章和待发布作品 | 是 | Idea / Draft / Ready / Published |
| Clip | 文章、帖子、图片、视频收藏 | 摘要与批注是；原始媒体是附件/引用 | Saved / Read / Archived |
| Task | 可执行事项，可源自文档中的任务块 | 文档内任务保留 Markdown 表达 | Anytime / Today / Scheduled / Done |
| Project | 跨类型文档的稳定筛选上下文 | 项目说明是 | Planned / Active / Paused / Done |

### 4.2 项目不是文件夹

项目是一级上下文，不是第五种笔记，也不是单纯目录：

- Note、Article、Clip 可以有一个可选的 `primaryProject`；Task 单独保留项目关联。
- 在项目内新建内容时自动带上当前项目。
- 项目页直接展示混合文档集合，不先经过概览、Hub 或二级入口。
- 混合集合显示文档类型标签；笔记、文章、收藏单类集合隐藏重复标签。
- 一个项目归档后，其内容仍保留在各自类型库中。
- 跨项目主题使用标签；首版不允许一个对象同时拥有多个主项目，避免组织模型失控。

### 4.3 直接归位，不设收件箱

应用不提供全局 Inbox，也不建立隐藏的“待处理”状态：

- Today 中的快速输入直接写入当天 Daily。
- 主动新建的短笔记直接成为 Active Note。
- 分享扩展传入的链接、图片或视频直接成为 Saved Clip。
- 独立新建且没有日期的任务直接进入 Anytime。
- 项目是可选属性；没有项目的内容保留在对应类型中，通过“未归项目”过滤器找到。

捕获时可以顺手选择项目，但不能用必填表单阻断记录。之后在文档属性中修改项目。

## 6. 总体窗口布局

默认只保留导航侧栏和主工作区。“今天”在正文顶部使用一张天气日历卡建立氛围与时间上下文：

```text
┌──────────────┬─────────────────────────────────────────────────────────────┐
│ 导航侧栏     │ 页面标题 / 路径                              已保存      │
│ 216–232 pt   ├─────────────────────────────────────────────────────────────┤
│              │                                                             │
│ 今天         │ ┌───────────────────┬───────────────────────────────────┐ │
│ 内容类型     │ │ 动态天气场景      │ 月历与 Daily 日期导航            │ │
│ 活跃项目     │ └───────────────────┴───────────────────────────────────┘ │
│              │ Daily 编辑器 / 文档集合 / 阅读器 / 任务集合              │
│              │                                                             │
└──────────────┴─────────────────────────────────────────────────────────────┘
```

布局约束：

- 主工作区永远获得最多空间。
- 不存在常驻中间浏览栏；导航侧栏可以隐藏。
- Today 页眉不增加额外入口；天气和月历直接进入正文阅读流。
- 天气日历卡与正文使用相同的 80% 内容宽度，不形成第三栏。
- 窄窗口下天气变为顶部横幅、月历在下方完整展示。
- 文档集合统一使用列表骨架；项目集合只额外提供“全部 / 笔记 / 文章 / 收藏”过滤。
- 编辑正文最大阅读宽度约 760 pt，但媒体、表格和项目看板可以突破该宽度。

### 6.1 Today 天气日历卡

- 左侧天气场景约占 55%，承载温度、天气、位置和随天气变化的动态氛围。
- 中间农历约占 18%，右侧月历约占 27%；选择日期后直接加载对应 Daily Markdown。
- 卡片高度约 218 pt，保持视觉存在感，但不取代编辑器成为页面主体。
- 晴天、云层、阴天、雨天和夜晚使用本地 WebGL2 动效；减少动态效果时保留静态画面。
- Core Location 获取位置，Open-Meteo 提供实时天气；数据不可用时日历仍然独立可用。

### 7.1 今天 / Daily

```text
│ 任务         │ 日期 / Daily 标题                                          │
│              │ 今天的重点                                                  │
│ 项目         │ Daily Markdown 编辑器                                      │
│  Note Down   │                                                             │
│  个人网站    │                                                             │
└──────────────┴─────────────────────────────────────────────────────────────┘
```

调整点：

- 主区域先展示天气日历卡，再进入 Daily 日期、标题、重点和 Markdown 正文。
- 月历始终可见，选择日期后切换对应的本地 Daily 文档，不再依赖隐藏面板。
- 天气动效负责建立氛围，操作文字保持克制；日历负责日期导航。
- Daily 是捕获入口，不是所有内容的永久存放处；选中内容可转为 Note、Article 或 Task。

### 7.2 笔记首页与正文

```text
┌──────────────┬─────────────────────────────────────────────────────────────┐
│ 笔记         │ 笔记                     搜索  项目  排序  [新建笔记]      │
│              ├─────────────────────────────────────────────────────────────┤
│ 文章         │ 最近更新                                                    │
│ 收藏         │                                                             │
│ 任务         │ 产品导航想法                 Note Down · 2 分钟前          │
│              │ 每日记录应该保持低摩擦……                                  │
│ 项目         │                                                             │
│  Note Down   │ 编辑器插件边界               未归项目 · 昨天              │
│  个人网站    │ `/` 菜单只负责文档内插入……                                │
└──────────────┴─────────────────────────────────────────────────────────────┘
```

集合页行为：

- 列表直接占据主工作区，不先经过中间栏或二级首页。
- 点击文档后，同一主工作区进入编辑聚焦态；返回时恢复原集合和筛选状态。
- 笔记、文章、收藏和项目文档集合都可按时间线或项目组织；时间线使用
  “今天 / 昨天 / 本周 / 更早”四级分组。
- 文档的项目、标签、状态和时间等属性属于编辑器本身，不依赖临时面板。
- 批量模式只在多选后出现，避免常驻工具条制造噪音。
- 指定项目不会改变内容类型；归档只改变状态，不移动真实文件。

### 7.3 笔记、文章与收藏

三个入口复用同一集合页和正文页框架，只是默认筛选条件不同：

| 页面 | 默认集合 | 主区域 |
| --- | --- | --- |
| 笔记 | `kind = note` 的文档列表 | Markdown 编辑器 |
| 文章 | `kind = article` 的文档列表 | 长文编辑器与发布入口 |
| 收藏 | `kind = clip` 的文档列表 | Reader、媒体预览与个人批注 |

单类集合不重复显示类型标签。项目等混合集合显示类型图标，并在列表上方保留
类型筛选；组织方式和类型筛选使用两个独立的紧凑图标组。

### 7.4 任务

```text
┌──────────────┬─────────────────────────────────────────────────────────────┐
│ 任务         │ 分组方式                 [日期]  项目  状态        │
│              ├─────────────────────────────────────────────────────────────┤
│ 笔记         │ Note Down                                                   │
│ 文章         │ ○ 完成首页信息架构                         7 月 20 日       │
│ 收藏         │ ○ 修订内容模型                                             │
│              │                                                             │
│ 项目         │ 个人网站                                                    │
│  Note Down   │ ○ 修改 About 页面                                          │
│              │ 已完成                                                     │
└──────────────┴─────────────────────────────────────────────────────────────┘
```

- 任务页不提供 Inbox，也不与文档集合强行共用页面。
- 任务可在同一页面按日期、项目或状态分组；分组切换不创建二级页面。
- 任务页与文档页共享分组控件、列表边界和紧凑条目卡；日期分组使用时间线
  串联日期节点。
- 任务卡只展示标题及当前分组尚未表达的项目、状态或日期，不在条目中重复组标题。
- 状态与日期是两个独立字段，不再用 Today / Upcoming 冒充任务状态。
- 文档内创建的任务保留来源锚点；任务详情可以回到原文位置。
- 首版不做依赖、工时、团队指派和复杂路线图。

### 7.5 项目文档集合

```text
┌──────────────┬────────────────────────────────────────────────────────────┐
│ 项目         │ Note Down                                                   │
│  Note Down   ├─────────────────────────────────────────────────────────────┤
│  个人网站    │ [全部]  笔记  文章  收藏                                   │
│              │                                                             │
│              │ 产品导航的三个原则       笔记   信息架构       刚刚          │
│              │ 本地优先写作不是离线模式   文章   草稿           今天          │
│              │ Reflect Daily Notes         收藏   reflect.app    12 分钟前     │
└──────────────┴──────────────────────────────────────────────────────────────┘
```

- 项目页本质是 `projectId` 筛选下的混合文档集合，不是仪表盘或文件夹首页。
- 项目页固定按时间线组织，不再展示无意义的“按项目”分组入口；顶部只保留文档类型筛选。
- 笔记、文章和收藏使用同一卡片模型；列表只保留标题、更新时间和同行的必要
  上下文标识。
- 类型视图使用色点与项目名，项目视图使用类型图标，避免重复当前页面已经表达的
  归属信息。
- 类型筛选状态在进入文档聚焦态后保留，返回项目时恢复。
- 侧栏项目名称原位编辑并保存在本机；列表名称定宽、尾部渐隐，不显示省略号。
  右侧竖状条始终保留并略高于文字视觉高度，悬停或键盘聚焦时在其左侧显示编辑入口。

### 7.6 发布

- 发布页只展示用户从笔记、文章整篇或文章正文段落主动发起的发布草稿，不扫描或自动收录
  所有 `Draft / Ready` 文档。
- 顶部只保留待处理、队列、已发布和失败状态；失败入口仅在存在失败任务时显示。
- 当前只支持 X；发布草稿复用集合页的列表边界与紧凑卡片，只展示来源类型、标题、
  X 标识和更新时间。
- 点击条目进入发布工作区；通过 X Web Intent 交给用户最终确认，应用不保存账号凭据，
  也不把“打开 X”误报为发布成功。
- 未完成草稿再次发起时复用原草稿；发布成功后再次发起才基于新 revision 创建草稿。
- 移除发布草稿不删除来源文档，来源更新也不能静默覆盖已经固定的发布 revision。

## 8. 全局创建与搜索

### 8.1 `⌘K` 命令面板

统一搜索以下对象：

- 页面与命令。
- Note、Article、Clip、Task、Project。
- 标签和 Smart View。
- 最近打开与常用动作。

结果按类型分组，支持别名和拼音关键词；先展示最近和上下文相关结果，再展示全局结果。

### 8.2 新建规则

- 全局新建按钮打开轻量菜单：短笔记、文章、收藏、任务、项目。
- 在项目中创建时自动绑定该项目。
- 在 Today 中直接输入默认写入 Daily；选择内容后再转成其他类型。
- 从系统分享进入的链接、图片和视频直接保存为 Clip，不弹出复杂表单阻断捕获。
- 没有选择项目时保留为“未归项目”，但它仍属于自己的内容类型，不进入中转区。

### 8.3 文档 `/` 菜单

`/` 菜单只解决“在当前文档插入什么”，不承担全应用导航与设置：

- 文本：标题、列表、任务、引用、代码、分隔线。
- 内容：图片、文件、表格、链接、收藏卡片。
- 结构：高亮块、折叠、模板、目录。
- 扩展：只显示当前上下文可用的发布或插件动作。

## 9. 视觉与动效基线

### 9.1 视觉层级

- 使用 SF Pro / PingFang SC，正文 15–16 pt，列表正文 13–14 pt。
- 背景只使用两个常驻层级：导航侧栏和主工作区；天气日历卡属于正文内容层级。
- 分类栏和分组标题都不展示统计数量；卡片只用于列表边界和可点击条目，层级依赖
  1 px hairline 与轻微色差。
- 文档正文与集合列表都占主工作区宽度的 80%，左右各保留 10%，切换时保持
  内容基线稳定。
- 仅保留一个品牌强调色；状态同时使用文字或形状，不能只依赖颜色。
- Reicon 通过语义图标映射使用；侧栏搜索、新建、编辑和设置图标统一为 16 px
  视觉尺寸与同级颜色，列表顶部控件沿用相同规格；描边图标使用 1.8 px，系统级行为可使用
  SF Symbols。
- 侧栏项目仅在选中时使用打开文件夹图标，其余项目保持关闭文件夹状态。

### 9.2 密度

- 导航行高约 30–32 pt。
- 内容列表行高约 48–50 pt；只通过细边框、轻微色差和悬停位移表达可点击性。
- 工具栏高度约 44–48 pt。
- 采用 4/8 pt 间距体系，避免初版大块无效留白。

### 9.3 动效

- 列表选择和对象转化使用 120–180 ms 的短动效。
- 只在表达来源与去向时使用 spring；除天气场景外不做持续漂浮和装饰动画。
- 天气场景是唯一允许持续环境动画的区域，并在窗口失焦或减少动态效果时停止。
- 遵守 macOS Reduce Motion；键盘操作不等待动画结束。

## 10. 技术路线修订建议

### 10.1 推荐改为 Electron 主壳

在需求已经明确为富 Markdown、插件化文档、统一文档集合与 Today 天气日历卡，并以 Codex/Obsidian
的交互质量为参照后，
建议把主壳从 `SwiftUI + WKWebView` 改为：

- Electron 主进程：窗口、文件、SQLite、索引、发布队列和安全 IPC。
- React 19 + TypeScript：整个应用壳与编辑器 UI 使用同一组件体系。
- Tailwind CSS 4 + CSS Variables：设计 token 与主题。
- Radix UI：菜单、Popover、Dialog、Tooltip 和键盘/无障碍基础。
- Motion/Framer Motion：少量空间和状态动效。
- Milkdown/ProseMirror：Markdown 所见即所得与 `/` 插件。
- CodeMirror 6：源码模式。
- unified/remark：统一 Markdown parse/serialize 与发布转换。
- better-sqlite3 + FTS5：本地索引和应用状态。
- Swift 小型原生 Target：只负责 Share Extension、App Group、Keychain 和必要的 macOS 能力。

该选择不是为了跨平台，而是为了让壳、编辑器、命令系统和插件 UI 共享同一运行时，删除当前
Swift/WKWebView 编辑器桥接的复杂度。

### 10.2 不照抄 Codex 的依赖组合

- 状态管理首版优先 Zustand 或少量 React Context，不因 Codex 包含 Redux 就直接引入 Redux。
- TanStack Query 只包装真正的异步 IPC 查询，不把本地同步状态伪装成服务端请求。
- 不引入 xterm、node-pty、地图等与笔记产品无关的依赖。
- Electron Renderer 禁止 Node Integration，启用 Context Isolation、Sandbox、严格 CSP 和白名单 IPC。

### 10.3 代价

- 安装包和基础内存高于纯 SwiftUI。
- Share Extension 与系统服务仍需维护少量 Swift/Xcode 工程。
- 原生模块需要随 Electron ABI 构建、签名和公证。

这些代价需要接受，但它们比继续维护两套 UI 状态、两套组件体系和复杂 Editor Bridge 更可控。

## 11. 后续顺序

1. 确认本文件的信息架构、一级导航和两区布局。
2. 只制作 Electron/React 静态壳，使用假数据走查 Today、Notes、Project 三个页面。
3. 通过窗口缩放、键盘导航、浅色/深色和 Reduce Motion 验收布局。
4. 再接入 Markdown 文件与编辑器，完成 Note 的真实读写。
5. 按 Daily/Note → Project → Article/Publish → Clip → Task 顺序补业务纵切。

在第 1–3 步完成前，不继续扩展账号、发布、插件 SDK 或复杂索引。

## 12. 页面验收标准

- 打开应用后 1 秒内能看懂“现在在哪里、当前对象是什么、下一步能做什么”。
- 在 Today、Notes 和 Project 之间切换，不需要理解文件路径或数据库概念。
- 任一内容都能从类型视图和所属项目两条路径找到。
- Calendar 不得独占页面或形成第三栏，主编辑器仍是主要工作区域。
- 不存在全局收件箱或隐藏的待处理队列。
- 主界面不存在常驻浏览栏或辅助面板入口。
- Project 页面首屏直接展示混合文档集合，并可按笔记、文章、收藏筛选。
- Today 天气日历卡与正文左右基线一致，切换日期不触发正文宽度重排。
- 项目名称可在侧栏原位修改；长名使用渐隐而不是省略号。
- 核心路径有完整键盘和 VoiceOver 语义。
